## 6. General backtesting critiques that apply directly to LLM agents

| General methodological critique | Why it applies to LLM trading | Evidence / metric | Required performance context | Exact reference |
|---|---|---|---|---|
| **Backtest overfitting and false positives** | A strategy can appear successful because researchers select among many specifications, windows, prompts, tickers or model settings. Prior work documents backtest overfitting as a false-positive problem and warns that walk-forward designs can still overfit a single validation set. [13] | No LLM-specific return is asserted here. The methodological failure is selection among many candidate strategies or configurations. | Asset universe: **NOT REPORTED**; exact dates: **NOT REPORTED**; transaction costs: **NOT REPORTED**; baseline: **NOT REPORTED**. | Applies to FinMem, TradingAgents, FinAgent and any LLM agent when the researcher chooses the best prompt, ticker, seed, temperature or period after observing results. | http://arxiv.org/pdf/2209.05559 |
| **Deflated Sharpe Ratio** | The DSR corrects for selection bias, backtest overfitting and non-normality, precisely the distortions created when many LLM-agent variants are tested and only the best Sharpe is reported. [1] | DSR is a correction framework, not a reported LLM trading result. | Asset universe: **NOT REPORTED / not an LLM trading experiment**; exact dates: **NOT REPORTED**; transaction costs: **NOT REPORTED**; baseline: **NOT REPORTED**. | Use for any FinMem, FinAgent, TradingAgents or FinGPT study that reports a selected Sharpe without accounting for the number of prompts, models, seeds, assets and windows tried. | https://www.pm-research.com/content/iijpormgmt/40/5/94 |
| **Combinatorial Purged Cross-Validation and PBO** | A 2024 study finds CPCV superior to traditional validation methods for mitigating overfitting, with lower Probability of Backtest Overfitting and a superior DSR statistic. [12] Purging and embargoing are especially relevant where LLM prompts or news context overlap adjacent observations. | Exact PBO and DSR values: **NOT REPORTED** in the cited evidence. | Asset universe: **NOT REPORTED**; exact dates: **NOT REPORTED**; transaction costs: **NOT REPORTED**; baseline: traditional methods, specific baselines **NOT REPORTED**. | General ML-for-finance evidence, not a direct audit of FinMem, FinAgent or TradingAgents. | https://dl.acm.org/doi/10.1016/j.knosys.2024.112477 |
| **Probability of Backtest Overfitting / multiple testing** | The PBO framework is the direct statistical response to selecting the best backtest from many candidate configurations. In an LLM setting, the candidate count includes prompts, role decompositions, memory settings, temperatures, seeds, model versions, tickers and windows. | No LLM-specific number is asserted; PBO should be reported rather than a single unadjusted best return. | Asset universe: **NOT REPORTED**; exact dates: **NOT REPORTED**; transaction costs: **NOT REPORTED**; baseline: **NOT REPORTED**. | Applies to all named LLM trading systems when the experimental search space is larger than the published table. | https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf ; https://papers.ssrn.com/sol3/Papers.cfm?abstract_id=2326253 |

## 8. Bottom-line methodological requirements

| Required control | Minimum reportable standard implied by the critiques | Failure if omitted |
|---|---|---|
| **Temporal integrity** | Freeze every input, news item, filing, fundamental, ticker membership list, corporate action and LLM knowledge cutoff at the decision timestamp. Add a post-cutoff test. | A historical test can measure memorized realized outcomes rather than forecasting skill. [4] [4] [10] |
| **Contamination test** | Run ticker/date masking, counterfactual perturbations and a memory-only condition; report prediction consistency and input-dependence metrics. | A model can retain predictions after material input changes, as in the **82.13%** counterfactual consistency result. [4] |
| **Universe discipline** | Pre-specify the investable universe and survivorship rule; do not select single stocks because they have the most accessible news. | Results can be driven by ticker selection and unavailable-to-live-trader information density. [3] |
| **Execution realism** | Report commissions, bid-ask spread, slippage, market impact, execution timing, turnover and borrow constraints. | The survey finds few cost models and no stated slippage modeling across its reviewed papers. [3] |
| **Stochastic reproducibility** | Report model version, prompt text, tool traces, temperature, seed, top_k, top_p, number of independent runs and dispersion, not only the best run. | TradingAgents returns vary across configurations; one deterministic run can hide the distribution. [2] [2] |
| **Multiple-testing correction** | Report the number of prompts, models, seeds, tickers, windows and strategy variants searched; use PBO, DSR and purged/embargoed validation. | A selected Sharpe can be a false positive from backtest overfitting. [13] [1] [12] |
